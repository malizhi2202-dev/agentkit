1产品全景

本章回答：agentkit 是什么、给谁用、由哪些能力组成、以及它刻意不做什么。

1.1一句话定位

agentkit 是一套「拿走就能用」的 Go Agent 服务框架：它不替你写业务，也不替你造模型，只负责把权限、出域、审计、降级、轨迹这五件最容易写出漏子的事，做成无法绕过的默认路径。

换成接入方工程师的原话：「我已经有一批 handler 了，现在想让 agent 也能调它们、并且知道它到底调了谁、拿到了什么、有没有越权。」 agentkit 的答案是 —— 那批 handler 你在声明时多传三个参数（路由、权限点、handler），剩下的模型工具清单、权限裁剪、出域脱敏、审计证据、轨迹回放，全部由框架按同一条声明推出来。

依据：README.md:11-16（框架用途）· docs/design.md:20-26（同一声明产出三件）· docs/guide.md:8-11（前置认知三句话）。本仓实测：18 个包、生产代码 10,641 行、341 个测试函数、82 个 .go 文件。

1.3能力地图（18 个包 × 六类能力）

组装

装配能力

kit 两阶段注册 + 拓扑定序 + 失败逆序回滚；preset 内置十种插件；engine 四必需注入点 + 一句 Handle。
想快速跑起来，只碰这三层。

判定

治理能力

authz 权限点声明与角色值域（宿主注入，包内零角色字面量）；tools 工具注册表与唯一授权谓词。

边界

出域 / 入域能力

model 唯一出域实现（端点策略 + HTTP 客户端）；web 唯一入域实现（路由 + 中间件 + 进程内直调）。判据是等号基线。

安全

安全与留痕

security 脱敏 / 不可关黑名单 / 不可信数据围栏 / 出域策略；audit 先脱敏再扇出，脱敏失败一个 sink 都不碰。

执行

执行能力

agent 多轮循环（预算/降级/轨迹/记忆四类/结论溯源）；session 无状态记忆装配；tools.Runner errgroup 并行 + 单步超时 + panic 隔离。

编排 + 接入

编排与接入

semantic 语义选工具；scene 场景按角色裁；playbook 预演/补偿；modelcfg 三级兜底；kitctx 显式上下文；im 平台接入。

1.4这个产品不做什么（边界即需求）

不做为什么（这是取舍，不是缺口）
不做前端 / 不做控制台 UI框架只交付 Go 包与判据。§6 的原型是"接入方用它装出来的控制台"的样子，供接入方照着实现，不是框架自带页面。
不自带模型、不认厂商协议只定义 ChatRequest/ChatResponse 与端点策略；模型名由接入方注入（框架不猜默认值）。
不做服务端会话存储session 是无状态装配点：同请求重发同结果，记忆句柄由调用方持有并回传。
不写死角色 / 模型名 / 默认预算角色值域由宿主注入；缺失的 Scope/Enforced/Window/StepTimeout 一律拒或不动，fail-closed。
不做独立子 module / 不引入 DI 框架搬运靠「整目录复制 + 一次 import 前缀重写」，已实测；依赖只允许标准库 + errgroup。
不做向量库 / RAG 检索 / 多 agent 编排框架零用户状态；记忆四类与轨迹由 agent 管，检索与多 agent 属接入方业务域。
不做限流 / 计费 / 租户体系身份与预算经 RequestContext 显式携带，配额与计费在网关或业务侧。

2核心概念

本章回答：读懂 agentkit 只需要掌握哪九个概念，以及它们之间怎么咬合。

2.1插件与两阶段注册：能力是可以关掉的

插件是框架里唯一的扩展单位：{Name, Declare, Apply, Enabled, Deps, Describe}。一个能力 = 一个插件，关掉一个能力不需要改代码。

两阶段注册把"登记"与"接线"分开：Declare 期只能往声明器里塞工具/路由/权限点（类型上拿不到装配根），Apply 期才拿到 *Kit 接线并注册停止钩子。这样做的理由是装配期必须先看清全局（拓扑排序、缺依赖早失败）。装配完成后再登记 ⇒ ErrLateDeclare，直接报错而不是静默吞掉。

kit/plugin.go:23 · kit/kit.go:91 · docs/design.md:28-34

2.2同源声明：一份接口，三份产物

同源声明是 agentkit 最省事也最危险的那个设计点：preset.Served(route, sample, perm, handler) 一次登记，同时产出 HTTP 路由、模型可见工具、权限点；参数 JSON Schema 由 Go 结构体反射（tools.SchemaFor），所需权限由 Schema 反推（RequiredFromSchema）。

收益是三者不可能漂移；代价是 HTTP 面与工具面耦合在同一声明上 —— 想"只给 agent 用、不开 HTTP"必须显式走 preset.Direct。另外，声明了权限点却没人判是最危险的假安全感，所以 web.Config.Authorize 未挂时 Build 后会输出告警而不是静默放行。

preset/preset.go:262 · preset/preset.go:247 · docs/design.md:20-26

2.3权限：唯一谓词、空角色不放行

唯一授权谓词是 tools.Registry.LookupAuthorized(name, role) → (tool, registered, allowed)。全框架只有这一处比较角色；scene/playbook/semantic 只是它的消费者。三态返回让"没注册"与"注册了但你没权限"可以分开诊断（分别留 unknown_tool / not_authorized）。

空角色 ≠ 默认角色：未判定角色不放行任何工具，连 RequiredRoles 为空的工具也不放行 —— 因为空 RequiredRoles 在判定式里意味着"公开"，返回空角色就等于 fail-open。权限点的 Scope（platform|project）与 Enforced（direct|funnel:<key>）零值即非法，没有默认值。

tools/registry.go:211 · authz/vocab.go:43 · docs/design.md:10-13

2.4出域 / 入域：等号基线

出域（主动发 HTTP）只允许 model；入域（对外提供 HTTP）只允许 web。判据不是"包含"而是等号基线：出域符号所在包集合必须恰等于 {model}，多一个少一个都判红；中立符号（Request/Response/Header）允许集是 {model, web}；新增的 net/http 符号必须先显式归类，未归类即红。另有旁路判据：非 model 包引用 HTTPDoer、或函数返回 *http.Response 也判红 —— 拿注入的 Doer 自己发请求根本不出现任何出域符号。

guard_test.go:578-586 · README.md:79-90

2.5降级与轨迹：绝不当成功，绝不无轨迹

降级有两种，都走"非成功、非报错"的收口：撞步数上限 ⇒ StepsLimited，模型不可用/超时/未配置 ⇒ Degraded，两者都带冻结文案 Notice，已发生的结构化结果照常返回，绝不返回空成功。轨迹是 TraceID + Seq 的步骤序列；缺 TraceID 直接拒绝进循环 —— 产生不了可回放的执行，就不产生执行。

agent/loop.go:124-146 · docs/design.md:15-16

2.6记忆装配：无状态、纯函数、不虚报

记忆装配固定顺序 Clear → Deletes → Edits → NewItems → Compress，是纯函数：同请求重发同结果；失败不产生半成品；未声明窗口（Window<=0）不压缩，也不虚报压缩。记忆的结构（四类分组/冲突/压缩文案）只归 agent，session 不复制任何结构。

session/session.go:75 · docs/design.md:43-48

2.7场景与剧本：把"这类问题用哪几个工具"变成可诊断的配置

场景是 {ID, Label, Tools}：业务想固定"这类问题只该用这几个工具"时用它，按角色裁完会逐条留原因（unknown_tool / not_authorized）。剧本是可逆流程：预演阶段零写入，执行失败的步骤逆序补偿，补偿自己失败则 best-effort 继续并记 CompensationProblems —— 绝不因为撤销失败把整件事卡死。

scene/scene.go:121 · playbook/playbook.go:97 · docs/design.md:71-74

2.8注入点与探活：框架不认识任何厂商

注入点包括时钟、日志、HTTPDoer、实体解析、IM 传输、模型探活。框架不猜厂商协议，也不替你做网络探测：modelcfg.Probe 由调用方注入，测试期可以零真实出网。探活失败只是候选不可用，不是整个解析器失败；每份配置套自己的 Timeout，Timeout<=0 在构造期就拒。

modelcfg/modelcfg.go:141 · docs/design.md:50-54

2.9脱敏与审计：证据不能自己盖章

脱敏是接口，实现必须给出 applied 证据（实际被移除/改写的字段路径）。审计的投递面只有一条路径 audit.Fanout：先过脱敏、再按注册顺序多播；脱敏失败 ⇒ 一个 sink 都不碰。脱敏凭据是未导出字段，外部无从伪造"已脱敏"。

audit/audit.go:228 · README.md:25

3.5接口一览

框架本身不预设业务接口：路由由接入方的声明生成。下表是随包样例（samples/agentkit-demo.go.txt）里的演示接口形状，用于说明"声明一次产出三件"。

入口方法路径 / 形式说明

4核心时序

本章回答：一条问题从进来到出去，中间经过谁；装配失败、剧本失败、模型不可用时又怎么收场。

4.1主链：一次对话的完整穿行

#参与方动作异常分支 / 判据
①调用方 → web带 RequestContext 显式身份与预算；缺执行方身份会被拒未带 TraceID 的请求不允许进循环（agent.trace_id.required）
②web中间件链（注册序 = 外层到内层）→ handlerhandler 返回 error 走统一 ErrKind 渲染，状态码与封套可注入覆盖

4.2装配：Declare → 定序 → Apply → （失败）逆序回滚

HAPPY PATH

装配成功

  1. 各插件 Declare：只登记工具/路由/权限点，拿不到 *Kit
  2. Deps() 拓扑定序：书写顺序不决定接线顺序（样例故意先 Use(loop) 再 Use(model)）
  3. 按序 Apply：接线 + 注册 OnStop
  4. 装配后路由表封存；再登记 ⇒ ErrLateDeclare
FAILURE

失败与停止

  1. 某插件 Apply 失败 ⇒ 已 Apply 者逆序回滚，不留半初始化对象
  2. Stop() 钩子 LIFO 执行，幂等
  3. 停止后各能力分档拒服务：未装配（Err*NotAssembled）≠ 已停止（Err*Stopped）
  4. 已知边界：装配失败不回滚宿主持有的对象（如宿主自己的 Router），由宿主生命周期负责

5.2加一个能力：只加声明，不加清单

SERVED

既要 HTTP 也要 agent

用 preset.Served(route, sample, perm, handler)。参数 schema 由 sample 结构体反射，所需权限由 schema 反推。适合"现有业务接口想让 agent 也能调"。

DIRECT

只给 agent，不开 HTTP

用 preset.Direct(tools.Tool{…})，自己给 RequiredRoles。适合内部动作（加备注、打标签）—— 对外暴露反而增加攻击面。

两个高频踩坑 ① 装配之后才登记 ⇒ ErrLateDeclare，登记全放 Declare 期；② 想挂停止钩子必须在 Apply 期 k.OnStop(...)，事后挂会被拒（engine 自己就是按插件写的）。

5.7停止与诊断：把"没装配好"和"已停"分开

现象含义怎么修
engine: 未注入…（聚合）四必需注入点缺项一次补齐；只想少一个能力就别用 engine，直接 kit.Use
kit: 尚未 Build…OnStop 只能在插件 Apply 期间调用在装配完成后挂钩子把那逻辑做成插件，在 Apply 里挂
ErrEngineStopped / Err*Stopped已停止，不再接新请求重启进程或重建引擎；Stop 幂等，可重复调
preset: ErrScenesToolsMissing场景引用了不存在的工具通常是删了接口忘改场景 —— 装配期失败正是它该发生的地方
endpoint.public / endpoint.unresolvable公网端点未批准 / 批准了但解析不出来逐主机写进 AllowPublicHosts；确认 DNS/内网可达

6.8边界态 · 空、错、载各一处

原型不能只画"有数据的漂亮那一刻"。以下三态是接入方必须实现的最小集：没有它们，用户第一次遇到空数据或失败就会以为系统坏了。

EMPTY · 无轨迹

endpoint.public
端点 api.example-model.com 落在公网地址，默认拒绝。请在 AllowPublicHosts 中逐主机批准。
这不是"重试就好"的错误：策略层拒绝会一直拒绝，重试只会放大问题。

三态的产品口径 空态要告诉用户"下一步能做什么"，而不是只写"暂无数据"；错误态要给出稳定 token（endpoint.public）与正确的修法（逐主机批准，而不是放开整条策略）；加载态要有明确对象（哪份配置在探活）与超时预期。

9常见问题

本章回答：接入前最常被问到的八个问题，答案都指向具体机制，不指向"理念"。

Q1我只想要一个 Go web 框架，能用它吗？

能，但只该只用 web：web.NewRouter → Register → web.NewServer 是一条独立的入域面。纯 handler 形态没有权限点，所以既不会告警也不受权限保护 —— 这是取舍：不想引入治理面，就别声明权限点。docs/guide.md:68

Q2为什么框架什么都不猜？我漏个默认值就报错，太麻烦了。

因为"猜出来的默认值"在生产里是不可观测的：默认角色会变成隐式放行，默认窗口会让用户以为记忆被压缩了，默认步数会让预算失控时没人知道。缺失就拒（Scope/Enforced/Window/Timeout/TraceID）是把配置错误暴露在装配期与请求入口，而不是让它悄悄降级成"看起来能跑"。docs/design.md:14

Q3空角色为什么不放行？我明明没给这个工具设任何角色限制。

RequiredRoles 为空在判定式里等于"公开"，如果空角色也放行，任何身份解析失败的请求都会拿到全部公开工具 —— 这就是 fail-open。legacy.export 这类"没声明角色"的工具，正确做法是显式声明 RequiredRoles，而不是指望空集放行。

Q4我能在自己的 handler 里直接发 HTTP 调模型吗？

技术上能，但那会打穿出域等号基线：guard_test.go 会把 net/http 的出域符号出现在 model 之外判红，另外还有旁路判据（拿注入的 HTTPDoer 自己发请求、函数返回 *http.Response）。正确做法是经 model.Client + EndpointPolicy，把 Doer 与策略注入进去 —— 脱敏/黑名单/围栏/端点准入才会生效。guard_test.go:552-586

Q5装配失败了，为什么我自己的 Router 没被清理？

框架只回滚它自己 Apply 过的插件，不回滚宿主持有的对象（如宿主构造的 web.Router）。这是已知边界：宿主对象的生命周期归宿主。docs/architecture.md:75

Q6降级了但 HTTP 还是 200，前端怎么知道这不是正常结果？

看两个布尔与文案：StepsLimited / Degraded 任一为真就说明收口不完整，Notice 是要展示给用户的冻结文案；Verdict 可能为空但结构化结果照常在。不要用"Verdict 为空"当唯一判据，也不要把降级当成失败弹错误页。agent/loop.go:124-146

Q7我想做多 agent 协作 / RAG 检索，这个框架管吗？

不管，而且刻意不管（§1.4）。框架零用户状态、零任务编排概念；多 agent 编排、向量检索、知识库都在接入方业务域，或者选择其它框架。agentkit 负责的是"单个 agent 进程内的治理与装配"，把多 agent 也塞进来会破坏它的零依赖与可搬走两个前提。

Q8搬到我们自己的 module 要几步？会有什么坑？

三步：① 目标 module 已有 golang.org/x/sync；② cp -r 整目录；③ sed 重写 import 前缀，然后 go build && go test。实测坑只有一个：errgroup 的 module 必须在下游 go.mod/go.sum 里，否则构建报缺包。守卫会自动适配抽取布局（它自底向上找 go.mod 推 module 路径）。README.md:102-140

还有一个"不是问题的问题" 本仓 go test ./... 根守卫有一条常驻红（TestGuard_AgentkitImportClassification，两种布局常量塌缩），它是测试夹具问题，不影响框架功能，但会掩盖真红。详见 .specs/CONTEXT.md §8.1，修法是一行常量改回宿主布局路径。
